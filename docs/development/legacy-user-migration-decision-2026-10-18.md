## 方案背景（不替代逐人选择）

建议分两阶段：先按组织承接登录身份及已购买权益，让老客户能用新版；历史场次、报告和录音继续留在旧版，按已确认的“备案后迁移”安排另做。新版已经有正式数据，任何方案都不能用旧库覆盖新库。

| 方案 | 用户能得到什么 | 代价和风险 | 判断建议 |
|---|---|---|---|
| A：先身份和权益，后历史 | 手机核验后使用新版，按原剩余期限和名额保留权益；旧历史仍去旧版查看 | 过渡期有两个入口，需要说明历史查看位置 | 推荐；与目前已确认的历史延期安排一致 |
| B：身份、权益、历史一起迁 | 一次切换，在新版统一使用和查看可验证的历史 | 需先完成历史归属、文件完整性和增量对账；准备更久 | 仅在历史迁移条件成熟后选择 |
| C：先继续旧版，仅新客户进新版 | 老客户暂不改变使用习惯 | 两套系统继续维护；新版功能不能直接惠及老客户 | 若暂时无法确认客户权益清单，可暂选 |

方案A是建议，不代表已获迁移执行批准；原有“历史备案后迁移”确认不需要重复决定。

## 哪些东西分别搬

| 对象 | 推荐处理 | 不能直接做的事 |
|---|---|---|
| 登录身份 | 核验手机号当前归属；若新版已有同手机号，先确认是本人，再复用身份 | 按姓名合并、创建同手机号第二身份、迁移旧token或验证码 |
| 密码 | 推荐通过正式短信流程设置新版密码；是否保留可兼容的旧密码摘要另行确认 | 未核验即重置密码；把密码/摘要写入普通迁移清单 |
| 组织与账号 | 旧组织映射到明确的新组织；一个身份在同组织只绑定一个业务账号 | 认为两库相同ID就是同一对象；用同名组织自动合并 |
| 管理角色 | 平台团队名单单独确认；组织管理角色按新版规则核验 | 把旧工作人员、旧boss字段全量升级为新版平台管理员 |
| 商业权益 | 按合同/交付凭据确认级别、容量、原到期时间；保留剩余期限 | 默认从迁移当天重新送一年；把内部授权伪造成商业订单 |
| 换绑次数 | 有证据则继承；证据不足的组织单列，需你决定赠予/承接口径 | 无证据默认全部清零 |
| 体验与等级 | 核实体验来源、是否使用以及原等级含义；有争议保留待审核 | 重复赠送体验、默认升级或自动通过旧申请 |
| 场次、报告、录音 | 后续按来源键映射、文件校验和已证明的历史组织归属导入 | 用当前成员关系猜历史归属；未知归属计入组织统计 |

## 建议你只需确认这张业务表

受控明细由技术方整理，手机号、合同等不提交Git。每个组织一行，缺项明确标“待核实”。

| 栏目 | 谁提供/确认 | 需要的决定 |
|---|---|---|
| 首批迁移组织、负责人和时间 | 你或指定运营负责人 | 先选1—2个愿意试用的组织，还是更大批次 |
| 权益级别、容量和准确到期点 | 合同/交付记录＋你确认 | 记录与旧系统不一致时，以哪份凭据为准 |
| 新版已经存在的同手机号/同名组织 | 技术方列冲突，你处理归属歧义 | 复用既有身份和正确组织；不能批量覆盖 |
| 缺证据的换绑次数、体验、等级 | 技术方列缺项，你定商业口径 | 逐项批准例外；其余正常批次不必等待 |
| 用户通知和旧版停止新开局时间 | 你或指定运营负责人 | 按组织分批切换，一场只在一套系统记录 |

## 实际执行顺序与交付证据

1. **只读盘点**：读取旧/新库聚合数量、权益分布、无手机号/重复手机号、同名组织、旧历史归属及文件缺失情况。现已完成用户、组织、旧权益及按用户统计的场次只读盘点，已产出逐人名单；尚未完成历史文件完整性与全部迁移对象盘点，不据此声称整体迁移准备完成。
2. **映射与冲突清单**：保留旧主键→新身份/组织/账号主键的映射。已在新版产生的场次、文件和绑定保持原样；冲突组织暂停，不猜测归属。
3. **隔离副本演练**：验证数量、有效期、容量、跨组织拒绝、重复执行、失败中断及恢复；每笔带固定来源键，避免重跑重复开权益。
4. **给你看样例结果**：列明一个组织迁前/迁后的身份、账号、权益、可访问内容及差异；由你确认具体批次。
5. **备份后小批量执行**：保存新版库及相关文件备份，执行受控脚本；客户实际登录并核对权益。全量扩批须先通过首批验收。
6. **历史后迁**：先保留旧版只读查看能力，历史来源不清的记录继续标未知。文件元数据与对象必须成对校验，不能只搬数据库路径。

## 失败时如何处理

只撤回该批可识别的新增映射和授权，不覆盖新版整个库。若该批用户已在新版产生新场次，先停止该批后续写入并做差异清单，不能直接恢复整库抹掉其他客户的新数据。历史或身份冲突不可解释时暂停该组织，其他已确认组织可继续。

## 当前结论

本轮交付的是判断材料，没有执行老用户迁移，没有承诺旧账号已经能登录新版。你可以直接按实际名单逐人做选择；技术方据此整理账号和组织映射、商业例外与执行预览。所有未选择项保持待定，最后再确认迁移执行。
