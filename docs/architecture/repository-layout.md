# 仓库目录规范

状态：文档与协作入口已整理；运行时代码的目标目录尚未迁移。目标沿用单体与现有三个前端，不引入新的 workspace 构建系统。

## 当前结构与问题

`server.js` 同时包含启动、初始化、路由和定时清理；`src/routes`、`services` 只拆出部分功能，业务定位仍需跨文件搜索。根目录还保留旧后台和维护脚本。目录清晰度必须通过逐步迁移解决，不能只在 README 展示目标树。

| 当前位置 | 当前职责 |
|---|---|
| `server.js` | 进程、应用、初始化以及多数业务入口 |
| `src/routes/`、`middleware/`、`services/` | 已提取的认证、管理、权限及服务 |
| `src/db.js`、`cards-db.js`、`sql-pg.js` | 数据库结构、工厂和 SQL 访问 |
| `public/` | 玩家端 |
| `enterprise-panel/`、`admin-web/` | 独立构建的两个 Vue 前端 |
| `tests/` | 已跟踪测试；旧 SQLite 隔离方式待改造 |
| `test/` | 本地遗留 bench，未纳入 Git |
| `scripts/` | 维护、迁移和历史部署脚本 |
| `admin-panel/` | 旧 Streamlit 实现 |

## 后端目标结构

以下目录随真实模块提取建立，不预先填充空壳。具体模块边界与依赖以[应用架构](../wqt-application-architecture.md)为准。

```text
server.js                       # 进程生命周期与启动调用
src/
├── app.js                      # HTTP 中间件、路由与静态应用装配
├── platform/
│   ├── identity/               # 账号、登录、密码、设备会话
│   ├── organizations/          # 组织、成员、邀请码、组织期限和名额
│   └── access/                 # 身份上下文、角色和租户校验
├── game/
│   ├── sessions/               # 开局、事件、结算、历史与复盘用例
│   ├── activities/             # 活动及场次关联
│   └── cards/                  # 卡牌、版本、快照、套装
├── integrations/                # OSS、短信、AI 等外部适配
├── db.js                       # 迁移期间保留主库兼容入口
├── cards-db.js                 # 迁移期间保留卡牌数据源入口
├── sql-pg.js                   # PG 查询与后续事务能力
├── config.js                   # 运行配置
└── paths.js                    # 路径入口
```

Learning 与 camp 在功能或接入工作开始时建立业务模块，不将空目录视为产品能力。

## 归属与依赖规则

| 内容 | 放置原则 |
|---|---|
| HTTP 解析、响应 | 对应业务模块的路由文件 |
| 一次业务操作的规则 | 对应模块的服务/用例；简单操作无需强制分层 |
| 模块数据访问 | 对应模块的数据访问文件；数据库连接能力保持共享 |
| 平台身份与组织规则 | `platform/`；游戏调用平台明确入口 |
| 外部 SDK 与协议转换 | `integrations/`；调用方先完成权限检查 |
| 自动化测试 | `tests/`，按模块或验收类型组织并纳入 Git |
| 可重复迁移与运维操作 | `scripts/`；运行条件与影响必须可查 |
| 需求、设计、验证与知识 | `docs/`，引用版本基线而不复制 |
| 构建、导出、临时调试产物 | 忽略的本地目录；不混入模块源码 |

避免无职责的 `common/`、`utils/` 或通用基础类堆积。组织端与平台端是使用视角，不分别复制活动和场次业务规则。

## 迁移批次与验收

| 批次 | 内容 | 验收要求 |
|---|---|---|
| D0 | 团队文档、流程与模板 | 可导航；规则和当前实现分开；历史知识保留 |
| R1 | 隔离 PG 测试环境，分离应用装配与进程启动 | 测试可创建应用且不自动监听、不隐式连生产；启动链路与路由顺序保持 |
| R2 | 提取 identity、organizations、access | URL、响应与实时权限行为保持；撤权、到期、角色测试 |
| R3 | 提取 sessions、activities、cards | 游戏闭环、内容发布与管理查询契约保持 |
| R4 | 提取外部适配，归档遗留脚本与后台 | 路径引用和构建部署验证；逐项核对后移动历史文件 |
| T1 | 固定场次组织归属 | 单独数据变更；A/B 组织转移场景、回填与迁移证据 |

R1–R4 是代码结构工作；T1 是已批准的数据行为改造，不隐藏在文件搬迁中。每批次形成需求关联、实现和证据，按 [CONTRIBUTING](../../CONTRIBUTING.md)闭环。

三个前端暂时保留当前根目录，避免同时修改 Vite、静态托管和部署路径。未来确需统一到 `apps/` 时，以独立变更记录构建及迁移收益；目前不为视觉统一搬目录。
