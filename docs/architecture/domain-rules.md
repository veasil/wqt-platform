# WQT 领域规则与运行约束

> 团队知识。核查日期：2026-09-10。当前实现、已批准规则和待实现缺口分别标注。
> 协作流程见 [CONTRIBUTING](../../CONTRIBUTING.md)，架构方案见 [应用架构](../wqt-application-architecture.md)。

## 1. 租户与历史归属

以下两项由需求提出方于 2026-09-10 明确确认，后续实施无需重新确认同一原则：

1. **organization 就是 tenant。** 沿用 `organizations.id`，不另建重复的 `tenants` 实体。旧 `enterprise_id` 是组织关系字段，名称兼容不代表另一个领域。
2. **组织场次永久归创建时的组织。** 老师从 A 转到 B，A 的历史场次仍归 A，不能因人员归属变化自动出现在 B 的经营数据中。这里约定的是归属不变，不是无限期保留数据的政策。

**实现状态：** WQT-002 已加入 organization_id / ownership_kind、数据库不可变约束、按场次归属的查询和私有文件访问。隔离 PostgreSQL 验证通过；尚未迁移生产。

2026-09-12 需求方在 [G-MIGRATION](../changes/WQT-002-subagents-refactor/migration-gate.md) 确认：历史无法证明的场次标记 legacy_unknown、仅平台核实且不计组织统计；新独立场次为 personal；组织创建者离开原组织后失去该场次访问，原组织管理员保留访问、新组织无权访问；跨组织及个人场次关联组织活动被拒绝，公共活动不改变场次归属。

实施时遵循：

- 新场次的归属来自后端核实的组织上下文；前端 ID 和 JWT 中的旧组织信息不能独立证明权限。
- 存量归属结合活动和历史证据核实，不按人员当前组织整库回填；无法确定的记录单列处理。
- 个人、组织和归属未知通过明确 ownership_kind 区分。公共活动不是共享场次授权，不引入共享租户实体。
- 资源读取、写入、统计、导出、文件、AI 上下文和后台任务均检查范围；活动与场次关联也须一致。
- 代理商业关系不自动赋予跨租户明细访问权。平台跨租户入口需要明确授权和审计。

仍待独立决定：多组织成员与切换、跨产品履历、代理授权、产品独立权益及数据保留/删除政策。不用这些未决事项阻止已经批准的可独立工作。

## 2. 身份、角色与有效期

当前 `users.role` 是全局字段，`users.enterprise_id` 表示单组织归属。不要提前把它描述为多组织成员模型。

| 角色 | 当前含义 |
|---|---|
| `boss` | 平台超级管理员 |
| `operator` | 平台运营，存在模块权限设置；具体端点须核查实际授权 |
| `enterprise` + 组织 ID | 该组织管理员 |
| `watcher` + 组织 ID | 该组织成员 |
| `watcher` + NULL | 独立个人用户 |

认证链校验 JWT、环境、当前设备会话和账号有效性。角色/组织中间件还会查询实时用户与组织；重构不得退回仅信任 JWT。当前每用户只保留一个有效设备会话，自助注册默认关闭，邀请码和后台建号是已有路径。

有效期以 `src/account.js` 为准：

- 组织用户跟随组织状态和 `organizations.valid_until`；独立用户使用自己的 `valid_until`。
- **NULL 表示未开通会员，拒绝访问；不是永久。** `boss` / `operator` 在当前实现中豁免。
- 永久会员使用 `PERMANENT_UNTIL` 常量；不要复制另一套哨兵数值。

这些是当前实现说明，不代表所有接口权限已经审计通过。业务角色、商业身份和产品购买状态不混为一个概念。

## 3. 游戏与卡牌约定

| 事件类型 | 含义 |
|---|---|
| `card_choice` | 选择卡牌选项 |
| `skill_used` | 使用数智技能 |
| `game_start` | 开局 |
| `game_end` | 结束 |

新增或改名事件时同步检查生产者、回放、统计和复盘查询。会话 ID、进行中对局等每标签页状态使用 `sessionStorage`；跨标签共享的登录 token 当前使用 `localStorage`。

对局结束是显式状态，结束后的自由体验不能继续计分、记操作历史或回传游戏事件。阶段顺序和数量来自本局 `cardsPerPhase`，不硬编码“启蒙期先开始”。场次展示遵循“时间-守望师名”。

卡牌有三层内容和一个有序套装：

```text
card_versions（版本）→ promote → cards（当前编辑内容）
                                      ↓ release
                              cards_released（发布快照）
                                      ↓ 有序引用
                                 card_groups（套装）
```

`cards.status` 使用 `pending` / `active` / `deleted`。选项存于 `options_json`，各选项包含 `text`、`consequence`、`attributeEffects`。版本接口当前存在编辑和删除路径，不能把版本库描述为数据库已强制 append-only。

游戏读取 `GET /api/cards?group_id=X`；未指定时取默认组，无组时回退每个 key 的最新快照。组内通过 `released_ids_json` 保持快照顺序。发布和组保存的复用逻辑需检查现有实现，不能绕过快照直接令游戏读取编辑表。

## 4. 数据库、配置与运行边界

- 业务时间主要为毫秒 Unix 时间戳；显示时注意 UTC+8。现有 `system_settings.updated_at` 是 `TIMESTAMPTZ`，不要声称所有列都是毫秒整数，也不要隐式更改其类型。
- DDL 与外键约束以实际代码/数据库为准。字段名表达关系不等于数据库已强制外键；不能从旧文档的 `FK` 标注推断完整性保证。
- `makePgApi` 提供 `run/get/all` 兼容入口，默认使用 `pool.query`；`withTransaction` 提供固定连接，事务内读取不重试。不能用多次池查询假定 `BEGIN` 和后续 SQL 属于同一事务。
- 当前读取可有限重试，写入不自动重试。开局/结算重试的去重和名额并发保护是专项改造，不能把“先查再写”当成原子保证。
- 业务码不能通过 `MAX(id)+1` 推导。查重只能减少冲突，数据库唯一约束和冲突处理才处理并发竞争。
- `loadConfig()` 中数据库非空设置覆盖环境变量；直接读取 `process.env` 的代码另行核实。敏感设置加解密依赖原密钥，不能假定每个落库值都已加密。
- 启动有建表、默认值写入、内容初始化与场次清理副作用；确认测试库连接之后才能启动验证。不要读取或输出无关的 `.env`、生产凭证或个人数据。
- 短信限流应在模拟与真实发送的公共路径生效；IP 限流依赖正确的代理配置，内存计数不提供多实例统一配额。


## WQT-006 · 2026-10-12产品验收确认增量

组织与用户的运营统计不决定授权：用户当前描述可汇总全部有效绑定账号的权益/角色标签，操作仍只使用选中账号的实时权限。按用户后台开启连续30天体验，独立于一次自主激活机会，不消耗该机会；正在体验时重复开启不延期。在线人数为当前有效登录会话、正常身份及匹配凭据版本的去重用户。

用户确认首次登录及邀请码新增绑定均可任选密码、人机验证通道后的短信验证码、微信API，包含平台管理员。微信待接入，不开放假入口；正式环境无配置好的人机通道时不接受短信单独验证。新身份仍需验证手机号并建立密码；邀请只指定绑定目标，不能证明本人身份。验证限额通过既有Redis按身份共享，绑定事务再次检查身份状态/凭据版本。后台权限不由前端用户标签或邀请码声明取得。

平台端本机技术交付与证据见[运营修订v2](../changes/WQT-006-account-permissions/admin-operations-v2.md)，用户产品验收与生产迁移仍未完成。

## 2026-10-14体验起算修订

需求方明确平台开通体验权益后由用户激活，从激活时刻起连续30天，凭活动码开局。此决定替代10月12日平台开通即起算的解释；资格按身份保存，账号的有效绑定仍必须实时验证。新增待激活授权和消费时间，既有有效期限保留。详细迁移/回退及验证见WQT-006/player-account-completion.md；本地已实现，未生产迁移。


## 2026-10-16 产品反馈确认

来源：[产品反馈执行单](../changes/WQT-006-account-permissions/product-followup-20261016.md)，本聊天逐项确认。以下为本地候选实现，存量迁移和生产启用另记。

- 同组织同一手机号身份只有一个未结束的账号绑定；组织管理员用该账号兼顾桌游，不再同时绑定同组织独立守望者账号。身份手机号全局唯一，一人仍可跨组织各有一个账号。停用账号不自动释放有效绑定；换绑历史与场次不移动。组织0也遵守新绑定规则。
- 新绑定由事务内身份行锁和数据库触发器约束，当前验证隔离级别为 READ COMMITTED。旧重复只盘点，安装写入约束不自动结束旧绑定。迁移前用 scripts/audit-organization-bindings.mjs 显式只读检查；不能以新写入通过声称存量已清理。
- 免费是无有效付费权益时的用户分类与回退入口，不是删除身份、免费账号或免费场次的理由。获得付费权益后默认进入适当业务账号，原免费历史仍保留。权益到期不自动删除组织。
- 平台组织默认列表仅显示有有效付费权益的组织；可筛选全部/无有效权益。此展示过滤不改变统计总口径、权限或历史归属。
- 桌游单一业务账号免选；一个有效付费业务账号优先。多个有效付费业务账号依据活动所属组织匹配；无明确组织的活动不得猜测归属，明确提示后可手选。活动码不授予组织成员资格。
- 卡牌预习资料仅有效付费账号可读，体验、免费、到期拒绝；此决定已确认，不再是待决定项。游戏卡牌的既有免费游戏边界不借此改写。
- 复盘生成不设卡牌张数下限，保留无场次、模型失败等真实失败反馈。旧 REVIEW_MIN_CARDS 不再参与复盘资格，遗留自由模式配置另议。
- 监督调整理由选填，0–10整数范围与正式保存仍由后端校验；加减即时雷达是草稿预览，确认才写入。新游戏不以录音保存为前提，未保存录音仍保留原场次归属，不能被新录音覆盖。
- 已停止录音可本机持久化并按身份隔离恢复，草稿保存原账号和场次、不保存JWT。上传使用当前实时授权且必须匹配原账号；成功上传或明确清除才删除匹配草稿。录制中强制刷新、清理站点数据不能承诺恢复。2026-10-16本机旧4组重复已依逐项方案清理，历史摘要不变；不表示生产存量已核查，见[本机收尾证据](../changes/WQT-006-account-permissions/uat-completion-20261016.md)。
