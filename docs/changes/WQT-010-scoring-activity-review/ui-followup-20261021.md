# WQT-010 · 2026-10-21 界面与活动创建修订

来源：本聊天用户五项明确修订及行式记录截图。此修订替代上一版分类页和活动审核流程；不是对上一版视觉的验收。

## 本轮确认的界面判断

- 可直接操作的输入保持展开，主要补充动作放底部通栏，不用额外说明替代界面本身。
- 同一配置在开局和创建活动之间共用表单组件、默认值和校验；不分别维护近似表单。
- 场次是复盘反馈的基本单元：一行展示活动名称、时间、状态，右侧为查看本局、复盘文档、提交/查看反馈。操作跟随对象，不再要求用户切分类寻找同一场数据。
- 查看本局为只读汇总，展示雷达图、伍力总分、选卡和操作记录；不替换或修改当前进行中的游戏状态。
- 不展示录音文件；录音采集与本机暂存恢复不在本次删除范围，已有文件不删除。

## 已授权的行为差异

1. 参与者姓名字段改为参与者年龄范围，两端同时填写或同时留空，范围 0–120 且下限不大于上限；记录于配置快照，不存个人名单。
2. 创建活动填写名称、地点、卡组、活动时间、游戏时长、模式、阶段卡数和年龄范围。正式有效权益创建条件保留。
3. 创建后立即为 active 并返回活动码，替代 pending 审核。同事务留下平台站内通知；平台管理员可知悉、修改配置或终止活动，创建者不因此获得管理权限。通知不是外发短信或邮件。
4. 活动预置配置供加入者开局时读取和调整；已开启场次仍使用各自保存的配置与卡牌快照，管理员修改不追溯改写历史场次。

## 复核与后续

- 改变的假设：活动创建无需平台先审批；“复盘反馈合并”是对象行及对应动作的整合，不能解释为保留四类二级导航。
- 新约束：共享配置 renderer/绑定与前后端校验；本局查看是只读；文档严格绑定所选场次；活动配置只影响后续开局。
- 当前复杂度由实际复用产生：`components/game-configuration.js` 供两个表单使用；`components/session-row.js` 统一所有场次行；`components/session-summary.js` 负责只读汇总和问卷字段。共用数据校验位于 `shared/browser/game-configuration.js`，没有引入新的前端框架或泛化组件平台。
- 通知与活动同事务落库，幂等重试不会重复通知；平台共享知悉状态，未读列表最多200条，顶栏轮询最多约30秒延迟。现有待审核活动保持原状态，不批量激活。
- 保留成本：活动配置字段、通知表及少量读取/知悉接口。外部短信/邮件推送、通知按管理员分别已读、地址标准化、更细时间窗口、旧版兼容页面、生产发布均未纳入。
- 本地未接通真实 AI/存储服务。本次验证了报告按场次入口与已保存文档的筛选下载，未声称真实 AI 生成和上传成功。
- 未发生需求降级；仅随明确新要求替换旧 UI 合约。修复测试夹具的旧选择器与旧断言后重验，不将旧界面的失效断言计为当前功能通过。
