Issue / PR：待建立

## 目标与范围

活动码保留直接输入，底部通栏按钮允许跳过后自主配置，后端验证权益后自动关联同时间、同地点活动。将“我的”改为“个人主页”，“活动”改为“发起活动”，将记录、文件、提交及查看反馈统一到“复盘反馈”。

变更前：新版玩家端强制活动码；后端付费可无码，体验必须有活动码。

2026-10-20 本聊天需求方确认：允许跨组织关联，活动归首位开局者的组织；同日同地点独立活动以活动码区分；付费和有效体验均可跳过。采用本轮提出的 UTC+8 自然日＋地点文本一致（去首尾空白）口径，无默认活动时自动建立。同地点的不同文字不推断成同一场地。

自动匹配仅针对本次新增的自动活动键；已存在活动、人工申请/审核活动和独立活动以活动码选择，避免猜测历史归属。自动活动结束后不隐式重开，同日同地的新独立活动使用自己的活动码。活动归属不改变每桌场次归属，不扩大对其他组织场次、反馈、文件的访问权限。

## 非目标

不扩大跨组织场次访问权限，不迁移历史场次，不自动合并或部署，不改动工作区既有无关修改。当前实现范围为新版 `/player/`，旧版兼容页面另行评估。

## 验收标准

| ID | 标准 | 验证方式 |
|---|---|---|
| AC-01 | 主导航为个人主页，个人页活动模块为发起活动 | 浏览器检查 |
| AC-02 | 复盘反馈按场次逐行显示名称、时间、状态；右侧查看本局、复盘文档、提交/查看反馈；不展示录音文件 | 浏览器交互及后端隔离验证 |
| AC-03 | 付费和有效体验可跳过活动码并自行配置；无权益、过期或撤销绑定拒绝开局 | HTTP + PG/Redis 隔离集成 |
| AC-04 | 同 UTC+8 自然日、同地点可跨组织关联，活动归首次创建者组织，每桌保留自身组织 | 并发及日期边界集成 |
| AC-05 | 首次并发只建一个自动活动，桌号不重复；重试不重复建局；活动关联失败回滚场次 | PG 并发、幂等与回滚集成 |
| AC-06 | 活动码展开输入，删除指定说明；底部跳过按钮通栏；可用活动码加入独立活动 | 浏览器及 HTTP 集成 |

## 确认与验收

AC-01/02 来源为用户本轮直接要求；自动关联领域边界及体验条件已由用户本轮回复确认。上述标准是对明确要求及边界的技术化表达；技术验证不等同用户业务验收。
