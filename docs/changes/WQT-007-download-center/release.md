## 未关闭的发布项

1. **原版认证缺陷**：src/routes/auth.routes.js 的 /api/auth/admin-login 仅凭手机号即可签发 boss/operator 登录令牌。平台页面当前使用三要素登录，但旁路 API 依旧存在，前端不调用不代表不可被调用。下载中心的 boss 校验不能弥补认证缺陷。2026-10-12 用户确认“先完成下载中心验证，暂不更改登录”。本次原样保留，不将该决定记作安全放行或风险接受。
2. **真实 OSS**：用户确认无测试 OSS，先完成其余验证。当前所有对象存储为替身；必须验证真实桶的 private ACL、匿名访问拒绝、权限错误、中文文件及内容一致性。
3. **生产运维**：指定发布负责人核对当前生产提交、数据库权限、可恢复备份、服务内存与代理超时，记录发布与回退版本。本地联调不是生产备份恢复或容量证明。
4. **产品验收**：需求方确认原版两个入口、目录和平台管理操作。截图或技术测试不代替该结论。

## 真实 OSS 验证步骤

在隔离数据库和专用测试桶/测试前缀中操作，不复用生产账号或发布实际客户资料：

1. boss 上传无敏感内容的中文文件，记录版本 UUID、SHA-256 和对象键。
2. 验证对象 ACL 为 private。对未签名 HTTPS 对象 URL 发起匿名请求，必须拒绝；检查桶策略没有绕过对象 ACL。
3. 有效会员经后端下载，检查中文文件名与 SHA-256；同一 token 下修改会员到期或组织停用后重复请求必须拒绝。
4. 未登录、普通用户的上传/审计 API 必须拒绝。所有成功下载有 requested 与 server_sent 同请求编号；模拟存储错误有 failed。
5. 仅删除本次登记创建的测试对象；失败时记录确切 UUID，不枚举删除整个前缀或存量对象。

## 部署与回退

完成上述门槛后才讨论生产放行。发布负责人应记录：批准人、提交 SHA、目标服务、备份位置与恢复检查、OSS 权限验证、发布后冒烟及回退目标。

部署使用原版 Node 服务流程，构建三个现有前端。不改变登录配置或主库连接。initDb 增加两张 download_* 表及一个索引，部署前须确认数据库角色可创建这些对象；新增过程失败会阻止服务继续启动。

回退代码到记录的原生产提交（本次基线 352edf1 仅供核对，不自动假设它仍是生产最新版本）。保留 download_releases、download_events、索引及私有 OSS 对象，不删审计，不回填/改变 users 或 organizations 数据。原版代码不引用新增表。回退后核对既有登录与桌游流程。

若发现公开对象或认证绕过，先由发布负责人限制入口/停用新功能并保留证据；删除文件不能撤回已经被用户下载的副本。不能以回退代码掩盖原版认证缺陷。
