# WQT-009 线上人机与登录故障排查（2026-10-27）

状态：已定位腾讯服务端套餐/计费阻塞与前端挑战初始化拒绝；等待服务所有者核实控制台。未恢复真实登录，未发布代码或修改生产配置。

来源：需求方本聊天反馈“上线后人机验证总是失败；admin 登录时密码跳不出验证，短信验证失败”。本轮范围为复现和定位登录故障，保留人机校验与短信限流；不购买套餐、不变更认证边界。

## 假设与实验

初始假设：线上密钥不完整、前端未调用挑战、供应商拒绝校验，或独立短信服务失败。以当前运行代码和真实请求区分，不以本地工作区代替线上版本。

- 新版香港应用 Pod 为 Running、ready，重启 0；运行进程报告 release `c8ad1fcf1338edb87fe27933a4a22bc2f3a8f921`。本次未独立核对该 release 与镜像源码摘要的一致性。
- 仅检查存在性：`CAPTCHA_ENABLED=true`，腾讯四项凭据及 Bmob 两项凭据均非空；未输出密钥值。
- 读取最近 168 小时、最多 5000 行日志并仅输出匹配聚合：11 次“天御校验接口报错”，错误码均为 `UnauthorizedOperation.Unauthorized`；该采样中未匹配到天御异常、Bmob 或短信发送/验证失败记录。无匹配不证明短信供应商正常。
- 在运行容器内加载现有验证码模块到独立 Node 进程，使用专用无效票据进行一次负向校验；临时在内存中提取供应商错误和 RequestId，不修改线上文件。腾讯返回 `CaptchaCode=-1`、`UnauthorizedOperation.Unauthorized`，Message 为“无有效套餐包/账户已欠费”。RequestId：`a30a392d-1022-4116-8253-87f722096357`，可供服务所有者向腾讯排查。
- 真实 admin HTTPS 页面、独立 Chromium 上下文、合成手机号及密码：SDK 已加载，构造函数及 `show()` 已执行；挑战初始化 `/cap_union_prehandle` 连续三次 HTTP 403，响应 server 为腾讯 HTTP 服务、body 为空。SDK 回调 `ret=0`、`errorCode=1006`、`errorMessage=get_captcha_config_request_error`；无挑战 iframe，页面最终显示“人机验证失败，请重试”。回调中的票据和随机串未记录。
- 首次浏览器实验的 SDK 容灾回调进入真实登录接口并收到 400；没有成功登录或取得会话。后续重复实验在浏览器层拦截登录请求，仍重现腾讯初始化 403。未尝试解答挑战或发送真实短信。

浏览器自动化的一次等待使用字符串形式被页面 CSP 拒绝；改为函数形式后完成观测，没有放宽线上 CSP。一次本地终端 GBK 编码输出失败，改为 UTF-8 后读取诊断结果；均未因此修改生产状态。

## 结论与边界

已证实当前服务端存在腾讯套餐/计费阻塞；具体是套餐无效还是账户欠费，需要控制台核实。[腾讯官方接口文档](https://cloud.tencent.com/document/api/1110/36926)将该错误定义为“未开通权限/无有效套餐包/账号已欠费”。

admin 未弹窗的直接原因是腾讯挑战初始化 403，而非未调用 SDK。403 是否由同一套餐状态、应用限制或其他腾讯侧策略造成，当前空响应不足以进一步区分。

代码顺序为人机复核通过后才调用短信发送；当前人机错误足以阻断短信发送。Bmob 是否另有配额、模板、收件或校验问题尚未验证，不将“已配置”或无日志匹配当作送达成功。

## 验证与恢复标准

本地命令 `node --test tests/frontend/captcha-loading.test.mjs tests/sms-provider.test.mjs`：24/24 通过、无跳过。全部为隔离替身，未访问真实短信供应商，不证明线上套餐、挑战或登录成功。

1. 服务所有者检查当前验证码应用的服务状态、有效套餐及余量、账户欠费；如需购买/续费，由所有者作商业决定。若仍有初始化 403，核对应用允许的正式域名及腾讯侧限制。
2. 套餐/账户状态恢复后，重新运行真实无效票据负向探针：应进入正常票据判断（专用无效票据通常返回 15），而不是供应商业务拒绝；无效票据仍必须拒绝。
3. admin 密码入口应能正常初始化挑战；由真实用户完成验证。检查密码登录与短信发送分别获得各自的新票据，之后验证真实短信收件、验证码登录及管理权限。
4. 若人机恢复后短信仍失败，再依实际 Bmob 返回定位，避免在前置人机失败时推断短信供应商根因。不能以关闭人机校验作为恢复方式。

## 工程复盘

改变的假设：密钥齐全、旧负向探针通过和静态页面可加载，不保证当前供应商套餐有效。服务端供应商拒绝与用户挑战失败是不同故障，当前通用提示使它们难以区分。

本轮无代码、schema、权限、生产配置变更，无新增运行保证或实现债务。诊断文档为未提交工作稿。现有回归缺少真实供应商套餐可用性的持续观测；供应商错误分类、RequestId 日志与套餐告警为待安排的后续改进，本轮未部署。重点概念：外部依赖的运行状态、前置失败对下游判断的限制、替身测试与真实服务验收的边界。
