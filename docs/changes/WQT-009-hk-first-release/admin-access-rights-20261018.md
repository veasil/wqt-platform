# 管理登录接续、组织权益编辑与老用户迁移决策

状态：实现中，未发布。来源：2026-10-18本聊天及需求方两项答复。

确认范围：管理端按钮沿用桌游已登录的身份，原会话到期不变；平台boss可独立修改组织容量、个人/团体/城市权益及到期时间；缩容保留已有账号、绑定和历史，超过容量阻止新增，不自动停用。老用户迁移仅形成判断文档，本轮不执行。

现状与根因：原“使用当前登录身份继续”仅在同源localStorage找到boss身份时显示；上线后scoring/admin分域，浏览器隔离存储，按钮条件不成立。组织编辑仅资料，权益仅固定续一年。数据库仍将套餐与1/5/20强制绑定，不能只增加表单而忽略运行约束。

设计边界：使用只允许正式admin来源的专用同站跨源iframe传递当前浏览器身份令牌，严格校验origin/source/随机请求号；只在明确点击后访问，不将令牌放URL、日志或后台代建会话。后端原认证、账号选择和boss授权不变；不存在有效平台账号时拒绝，保留原登录。专用桥接页面允许admin嵌入，其余页面保留禁止嵌入策略。

组织权益：商业组织继续以subscriptions为来源，独立容量替代旧固定容量CHECK；内部组织增加organizations.entitlement_plan标识显式组织授权，复用既有max_members/valid_until，不伪造商业订阅。旧内部账号在未设置该标识前保持原逐账号授权。修改不改变角色、租户、换绑次数、历史场次或已有账号状态；升城市级不会自动授予管理员角色。扩容交付空闲账号；缩容保留账号，限制新插入及新占用绑定，已有占用账号换绑仍按原次数规则。

迁移与回退：只替换两个已知套餐容量CHECK并加入正整数范围；新增可空内部授权标识，不回填历史。生产发布前核对旧约束及容量分布，备份后执行；不支持旧CHECK的自定义容量存在时，不能直接降级旧模式，需先导出差异并由负责人确认容量处理，不能静默删账号。代码回退须保留兼容新权益读取和容量约束的版本。

验收：跨域接续不创建新Redis会话、不延长有效期；恶意origin/source及无效令牌不能进入管理端。权益调整仅boss、事务审计且重复提交一次效果；并发邀请/绑定不能突破新容量，过期立即生效。内部及商业组织扩缩容、级别调整、失效与回滚均在隔离库验证。迁移文档明确未执行、已确认原则、待决事项和恢复界限。
