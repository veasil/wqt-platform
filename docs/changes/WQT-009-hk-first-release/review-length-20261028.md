# 复盘故事300–500字与并行插画

状态：实现完成，全部候选CI通过，待用户验收，未发布。代码提交22bc20cf2778cf3acd40add09ae775c012f06162，[PR #18](https://github.com/veasil/wqt-platform/pull/18)保持draft、未合并。来源：2026-10-28用户明确要求“故事文字要求放在300-500字。插画并行生图”。基于线上2ad6a56代码和其后纯证据提交c8648a0，独立分支codex/review-length-20261028。

## 问题与方案

生产两次复盘story请求分别51.42秒、51.18秒；插画约9秒，上传约1.7–1.8秒，合计约63–64秒。生产当前qwen-plus；提示词强制至少1500字、8–14段，前端等待整份JSON，再并行生成三张插画，最后上传。公开源文件与本地发布基线hash一致。两次生图均有一次429 Throttling.RateQuota；此事实不代表供应商固定只允许两个并发。

将story.paragraphs改为3–5段、正文合计300–500字，标题、插画说明、小贴士和公约不计入。同步去除逐卡详写与凑长篇要求，保留忠于真实情境、选择、后果、能力变化及禁止虚构的规则。保留三张插画Promise.all并行发起、按原场景顺序排版、单张失败仍保留文字和其他插画。

本次不更换模型、不引入流式或报告缓存、不改变保存流程、接口、权限和schema。7000-token参数是最大输出预算，不是实际输出长度；保持该预算，避免只降低上限截断JSON。300–500字是生成要求，不通过截断或隐式二次付费调用强制修正模型输出。

## 验收与验证

- AC1：实际报告请求提示词的正文要求为300–500字、3–5段，不再包含至少1500字/8–14段/逐关详写的冲突要求；保留原始事实和不虚构要求。
- AC2：三张生图请求在任何一张完成前均已发起；乱序完成仍按场景顺序入报告；一张失败不丢正文及其余两图；等待最慢的一张结束后组装最终报告。
- AC3：原复盘入口、少量卡牌可生成与显式场次不回退契约保持。

本地验证：`node --test tests/frontend/review-eligibility.test.mjs tests/frontend/review-generation.test.mjs` 12/12通过，0跳过；JS语法、lint、制品4/4与结构检查通过。新增回归已接入Browser contracts工作流。

首次并行测试发现原排版对短正文会把部分图分配到末段之外，导致请求成功却不展示；修复插图位置分配，短段落允许共用位置，场景顺序保持。覆盖1/3/5/8段×全部成功/单张限流共8组，以及原入口0/1/6张卡和指定场次隔离4组。采用可控Promise，第三张先结束仍不能提前完成；最终HTML保留所有成功插画与正文，无隐式额外付费生成或重试。

实际Chromium渲染312字、三段合成正文与三张占位插画，三图均加载且目视确认展示；截图位于受控本机 `C:/ArdenDev/tmp/wqt-short-review-layout-20261028.png`，HTML同名。未改变报告样式。

使用合成HTTP和可控Promise，不调用付费模型、不修改生产。该验证不证明真实模型字数遵循度、优化后实际耗时或三并发生图的供应商额度；线上429仍需后续独立处理，不能将并行视为保证三张成功。
