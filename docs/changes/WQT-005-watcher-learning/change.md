## 知识库建设边界（设计建议，未确认为架构）

学习网站是公司知识的面向学习者的发布入口。建议先建立可追溯的内容清单，再决定存储工具；当前不引入向量数据库、智能问答或新的租户实体。

建议每篇内容维护：稳定标识、标题、摘要、正文/媒体、原始来源、内容负责人、审核人、版本、更新日期、发布状态、对外可见范围与所需权益。课程目录引用已发布内容，新闻专题也可引用相同资料，避免一处更正后另一处仍传播旧版本。这是针对课程与新闻重复使用内容的当前需求提出的建议，具体模型尚未决定。

内容状态与权益状态应分开：未发布/待上传内容即使有权益也不可学习。对外付费资料不是公司内部知识的同义词；内部文档不能因“已拥有学习权益”自动公开。正式后端应对列表、正文、媒体下载与搜索结果统一验证可见范围，不能只在前端隐藏按钮。

建议后续顺序：①盘点现有培训、体系资料和新闻来源，确定内容负责人；②确认内部/公开/权益资料的发布边界及审核责任；③确认账号衔接、个人或组织权益、有效期及撤销行为；④实现发布和检索；⑤有实际检索需求后再评估智能问答。

待需求方决策：权益由个人还是组织持有，课程间是否共享权益，如何授予及到期；内部知识库权威来源和管理工具；第二模块目录；速递非免费部分的具体范围。原型“专题深读与学习资料”为待确认文案，不建立收费商品。“已拥有学习权益”开关仅演示状态，不暗示单一会员包。

订阅上线依赖：确认隐私说明、邮件用途、退订及删除机制，接入可验证的订阅服务与失败状态；本次不保存邮箱。
