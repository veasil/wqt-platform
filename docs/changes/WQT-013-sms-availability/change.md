## 目标与范围

在用户使用前发现低额度并通知负责人；发送发生服务故障时有独立通知。通知使用飞书，不依赖短信通道。
不自动充值、不更换短信供应商、不放宽身份验证、不向飞书发送手机号、验证码或密钥。

## 诊断证据

- `src/services/sms.js` 的 smsMode() 只判断客户端配置；没有余额检查，live 不代表余额充足。
- `src/bmob.js` 仅有发送与验证码校验；发送失败丢弃供应商结构化错误码，仅保留 message。
- sendCode() 捕获错误并返回给请求用户，没有运维通知。
- 当前运维 HTTPS 检查只验证公开配置与静态资源，不证明短信额度或送达。
- Bmob REST 官方文档 https://doc.bmobapp.com/sms/restful/ 未找到余额查询接口；文中 balance 为通知模板变量，不能当作余额查询结果。
- 官方错误码 https://doc.bmobapp.com/other/error_code/ 列出 10011 为 SDK 余额不足；10016 同时可能表示设备 ID 为空或 RESTful 额度用完，不能仅凭该码断言余额耗尽。
- 尚未读取生产余额、发送真实短信或复现此次供应商错误；用户报告是本次事故现象来源。

## 验收标准

| ID | 场景或检查 | 预期结果 | 验证方式 |
|---|---|---|---|
| AC-01 | 权威余额仍大于零，但已达到或低于预警阈值 | 主动通知指定飞书接收目标，包含环境、余额、检查时间与处理入口 | 注入余额结果与通知替身 |
| AC-02 | 余额查询失败或数据过期 | 标记未知并告警，不能显示健康或零余额 | 超时、无效响应、过期结果测试 |
| AC-03 | 发送出现供应商服务故障 | 独立告警；重复故障限频，恢复后可再次报警；不改变认证要求 | 供应商与通知替身测试 |
| AC-04 | 通知失败 | 可观测且有界重试；不拖慢短信请求，不泄露敏感数据 | 超时、日志脱敏测试 |
