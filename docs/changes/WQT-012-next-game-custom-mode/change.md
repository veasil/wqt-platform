## 验证记录

复现与根因：原 `write()` 仅在 POST 期间设置 `busy`。POST 成功、场次 GET 未完成时，本地 `state.ended` 仍为 false；倒计时可再次提交 finish。第二次请求在后端被正确拒绝，其错误可延迟出现在下一页。虚拟浏览器时钟必须在加载页面之前安装，才能控制已有计时器。

修复：`actionPending` 覆盖动作 POST、场次 GET 和待反馈刷新，倒计时在动作完成前不触发第二次结算，finally 释放标记。新局清除 session/state/card/selected/events/lastFeedback/scoreOverview/activity 和自动结算标记；录音继续由独立的 audioContext 绑定原场次。

### 2026-10-29 续修与验证

property 根因复现：手动结算的场次 GET 已返回 ended=true，但 `action()` 仍等待反馈列表。此时点击桌游导航可提前显示结算页，再点击“开启另一局”清空 state；反馈读取完成后，原 finish 回调再次调用 `ended()`，访问空 state 的 values，形成客户端 TypeError。修复前新增延迟响应测试失败，活动码页出现页面操作错误提示。

修复：结算页渲染必须满足当前 `state.ended`，旧回调在状态已清空或当前局尚未结束时直接退出。这是结算视图的有效状态约束；后端成功结算与录音不受影响。

布局修复：账号操作区允许换行，录音/反馈按钮不压缩；账号名保留可读宽度。在桌面保留录音或未确认操作时，导航独占一行；平板重新分配品牌与账号操作空间。亮暗主题保持同一结构。
