## 目标与范围

在正式发布前验证备份恢复、历史归属迁移和实际业务链路。先以 CI 合成数据完成可重复恢复演练和浏览器检查，再对明确指定的预发布环境执行真实服务联调。两类证据分开记录。

## 非目标

不操作生产库、不改线上 OSS ACL、不发真实短信或调用付费服务，直到测试资源与接收人明确。不默认批准 main 历史合并和生产部署。不声称合成数据等同存量副本或全量容量验证。

## 验收标准

| ID | 标准 | 验证方式 |
|---|---|---|
| AC-01 | 合成旧 schema 能真实备份、迁移并恢复到另一个独占数据库；行内容保持，未知归属不猜测 | PG16 pg_dump / pg_restore 实际执行、内容断言 |
| AC-02 | 恢复后重新迁移可重复；迁移后的归属和私有文件 metadata 在备份恢复后仍保持约束 | 二次迁移、迁移后备份恢复、不可变约束反向测试 |
| AC-03 | 浏览器专项和两个前端构建成为可重复 CI | Chromium 登录界面/认证下载检查；API 为替身，非完整业务验收 |
| AC-04 | 指定预发布副本迁移、完整浏览器业务链路和真实短信/OSS/AI 联调有版本与证据 | 环境确认后执行；目前待资源 |
| AC-05 | 发布负责人可据证据决定上线；未解决项与恢复期间新增数据处理明确 | evidence 和发布 gate，需求方最终判断 |

## 确认与验收

“继续”复用已提出的预发布演练方向；日常派工和合成测试无需重复审批。实际测试环境、账号、短信接收人和费用边界待明确。正式发布及本轮最终验收尚未完成。
