# 创心力、沟通力与下载中心：当前实现说明

来源：2026-10-16 本聊天用户要求解释实际 API 与下载方案。以下描述本地代码，不从文档中的历史上线记录推断当前线上版本。

## 创心力和沟通力共用一条服务端反馈链

浏览器调用 `POST /api/player/ai-feedback`，传 `sessionId`、`cardId`、`purpose`。`purpose=creative` 对应创心力，`purpose=communication` 对应沟通力。用户不向供应商直接发送请求，密钥只在服务端读取。

- 创心力先按正式技能操作保存玩家的创新方案（最长240字），在当前卡牌中加入D选项；反馈服务读取已保存的方案，不接受浏览器另塞一份未经保存的文本。技能加分由游戏规则计算；选择D自身不加分。
- 沟通力必须先在这张卡使用技能。服务端核对 `state.used` 和 `skillCards`，结合该卡情景与选项生成沟通建议。
- 两者都用当前场次快照的卡牌资料。输入包括情景、标题、选项和方案，不发送手机号/个人资料作为提示内容。

`src/game/player/feedback.js` 读取系统配置选择默认供应商和模型。当前代码支持 OpenAI、Google Gemini 的兼容接口、阿里云 DashScope、DeepSeek；统一发送兼容的 chat/completions 请求。数据库非空配置优先，再读取对应环境变量；具体本机/生产当前模型需按环境核实，不能把支持清单当成已配置清单。

运行约束：供应商请求20秒超时，单进程最多4个同时生成请求，429或供应商失败返回可见错误；新增反馈必须有有效付费权益，暂停或已结算场次不能新增。供应商调用前和写入结果前均重查状态，避免请求期间账号失权或场次结束仍写入。

相同场次/卡牌/输入摘要命中已存反馈时复用，避免正常重试重复计费；数据库锁防止同一输入并发生成。它不保证供应商已收到请求、但本地结果未提交时的绝对一次计费。当前生成期间占用数据库事务和连接；小规模可用，长队列/多实例全局并发限制尚未引入。

模型仅允许返回结构化文本反馈，不能评分或修改游戏状态。服务端检查输入与输出、拒绝非法结构和分数指令，界面转义显示。当前规则筛查不是完整内容安全服务；如扩大未成年人公开运营，需按真实案例验证安全规则和失败处置，不能把关键词检查当作完整保证。

## 下载中心已有实现

平台boss发布资料 → 服务端上传私有OSS对象 → PG保存版本、文件名、大小、SHA-256 → 有效付费账号查询最新版本 → 后端鉴权后传输文件 → 记录请求、拒绝、完成/失败审计。

- 玩家从新版导航的下载中心进入；平台在下载管理页面发布。资料由平台统一发版，不由个人账号随意覆盖。
- 对象路径使用 `download-center/`；上传设置对象private。浏览器通过受保护的后端接口下载，不得到可长期传播的公开OSS链接。
- 免费、体验或到期账号不能因为登录成功而获得付费资料。后端实时检查账号与组织，权限不依赖前端按钮。
- 传输完成审计表示服务端已发送预期字节；不声称用户已实际阅读或永久保存文件。审计写入失败时不能伪报成功。
- 单文件上限50MB；当前上传采用内存方式。扩容前应测真实并发与内存，不能从一个文件成功推导高并发容量。

该方案在当前Express/PG单体和已有OSS上即可实现，不需要新增文件中台。后续确有需求再考虑资料分类、按组织/套餐分发、多文件目录、大文件直传或异步任务；这些都涉及新的产品/权限边界，本次不预先引入。
