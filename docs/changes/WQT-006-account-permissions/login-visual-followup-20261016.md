- L03：修复主界面选卡图标与文字中轴错位、外框高度问题，保持游戏阅读面及左栏布局。
- L04：删除监督页“重置伍力为3”“导出本局JSON”两个入口及闲置绑定，其他报告导出不变。
- L05：监督桌面左右框固定同高，展开左侧调整后在框内滚动；右看板独立滚动。窄屏上下排列保持各自高度边界，末尾控件可达。
- L06：我的→反馈中长问卷和展开其他意见都使用固定容器与内部滚动，不撑长整页。

## 根因证据与分工

短信：.env中Bmob两项真实配置存在（只检查布尔存在，不输出值），8188恢复启动器白名单仅载入captcha/OSS/AI，没有载入短信；NODE_ENV=test使sendCode走mock而非报错。增加显式--live-sms，默认测试继续隔离真实发信。

腾讯：旧脚本每次点击串行GET verification-options→首次下载TCaptcha.js→构造/show。配置接口本机62ms；子代理同轮样本配置67ms、SDK165ms，只是一组本机样本。按腾讯[Web接入](https://cloud.tencent.com/document/product/1110/36841)沿用现有版本SDK动态加载及show，不借机升级接口。

主界面：flow.css的按钮原flex居中，被player.css覆盖成grid后未设justify-items，固定宽图标偏左而文字居中；两层viewport min-height与padding叠加撑高。监督只有右框固定高度，左框随details增长；反馈表单无高度边界。

主控独占SMS能力、受控启动器和本制品；visual_alignment子代理独占player.js/css及独立布局测试；captcha_latency子代理独占三个前端验证码工具及独立测试。子代理继承当前模型，不声称不可用Luna。不得改变其他工作区文件或提交。

- Python真实浏览器检查新8188：SDK可用、无页面异常，未自动展示挑战或请求短信。首次将“iframe数量=0”当作未弹窗判据失败；进一步检查确认腾讯SDK自行创建离屏预热iframe，祖先opacity=0、top=-1000000px，故使用可见弹窗/显式show调用而非iframe存在判断。未修改供应商SDK。

## 工程复盘

改变的假设：恢复服务时“环境里有密钥”不表示隔离子进程已经继承；第三方SDK存在iframe不表示用户看到弹窗；子表内滚动不等于外框高度固定。新增保证是公开能力如实区分mock/live、加载失败有边界且可重试、展开前后容器与页脚几何不变。未引入新依赖或调整认证权限。保留债务：真实短信收件和第三方不同网络下的挑战速度仍需体验验证，不增加分布式短信配额/通用加载框架等额外抽象。
