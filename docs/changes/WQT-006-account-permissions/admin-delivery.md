## 实现与操作路径

1. 平台管理员手机号登录 → 多账号显式选择 → 当前账号/组织持续展示。无账号、失去绑定、权限不足和服务故障分别处理。新模型的旧用户/组织深链接转入账号与权益，旧模型保留原运营登录行为；手机宽度使用抽屉导航。
2. 账号与权益 → 组织与套餐 → 交付新套餐：选个人/小组/城市，自动交付组织、套餐及1/5/20个账号；个人/小组首期一年，城市首期明确填写到期。成功回执列出组织、套餐、账号和期限，再进入使用者绑定，不把未绑定状态说成已交付给人。
3. 查看组织账号 → 首次绑定或换绑：可以选择已有身份，也可先核验创建新身份再回到绑定。首次绑定不扣次数，换绑提示旧人失权及历史、角色保留，次数按整份套餐计算。管理员账号的绑定/换绑在本页面关闭，待受控管理规则完善。
4. 续费一年：预览原期限与新期限；提交只传套餐ID和固定请求编号，服务器从原到期日与当前时间较晚者增加一个日历年；续费不改变账号或重置换绑次数。
5. 身份与手机号：核验创建、同一人换号、分别停用身份/账号/组织，说明影响范围并填写原因；操作记录可追踪实际操作者身份和执行账号。
6. 活动创建/编辑/审核接入新接口要求的请求编号与结果未知恢复。活动参与统计在新模型中明确为账号数。

## 失败、修复及回归防护

- 换号先消费短信再检查已完成结果，导致已提交操作不能直接恢复：移动短信消费到新操作事务路径，持久化重放先实时核验boss再返回已完成结果。新增无需补发短信的重放回归。
- 换号重放无条件删身份会话，会误删换号后的新登录：Redis会话记录登录时的凭据版本，撤销只匹配旧版本；PG凭据版本仍实时校验，Redis失败不能恢复旧JWT权限。HTTP回归验证新登录在重放后继续有效。
- 全量回归首次31通过/1失败，仅批量发布具名共用回调与路由快照不一致。仅更新两条回调名称预期，保留所有路由/角色中间件及顺序检查，重验32通过。
- 真实浏览器最初失败为测试环境缺所需Chromium、旧选择器点击Element Plus内部覆盖层、组织URL尾斜线及玩家欢迎遮罩。使用已安装Edge并按实际可点击控件、合法URL和欢迎入口修正测试；未降低产品标准。完整重验通过。
- 合成浏览器增加第二个上下文后，Windows日志管道满导致静态服务加载停顿；持续消费测试子进程日志后重验通过，不改变产品服务。

## 工程复核与遗留

- 改变的假设：token存在不等于业务账号可用；手机号不是业务账号；请求超时不等于写入失败；验证码一次性消费不能阻断已提交结果恢复。
- 新增不变量：每次商业操作固定输入与编号；结果未知时不能生成下一笔替代操作；身份、账号、组织分别停用；换号重试只影响旧凭据会话。缓存只作恢复辅助，后端仍实时检查权限。
- 抽象只覆盖已发生的套餐与活动写入恢复、固定续费日期；没有通用权限框架、共享包或新schema。恢复信息按身份/账号/业务范围放在当前标签页会话存储；密码和短信不持久化，关闭/刷新敏感表单后需从身份列表核对结果。
- 当前债务：管理列表仍全量读取/前端过滤，规模增长后需分页；已有大chunk构建警告；待接通页面、管理员保护和体验后台设置仍待后续工作。生产存量映射和上线门槛不由本轮前端验证代替。
