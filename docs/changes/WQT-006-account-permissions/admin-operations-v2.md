# WQT-006 · 平台运营验收修订 v2

状态：2026-10-12需求方在本机产品验收提出7项修订，本机技术交付完成；需求方于2026-10-12明确回复“验收通过。”，平台管理端v2产品验收通过。原[平台交付记录](admin-delivery.md)保留为v1历史证据，本轮结果另记。

## 已确认范围

- 运营用词：组织与权益、守望者账号、用户；用户页为第二重点，组织页第一。操作记录移至次要入口，移除游戏分析/数据审计/复盘测试菜单，系统设置接通。
- 继承原账号页面的资料、权益查看、邀请码、在线会话/强制下线等适用功能；旧字段修改、移动用户不用于绕过新绑定模型。
- 后台给免费守望者账号的当前用户开启连续30天体验，按用户保存，不消耗自主激活机会。正在体验时不因重复点击延长期限；过期后平台可再次开启，留操作记录。原自主激活的一次资格保持独立。
- 用户分类汇总所有当前可用绑定账号的权益描述，免费/体验中/有权益以及组织管理员/平台管理员可一键筛选。管理员与权益标签可以重叠，汇总仅作运营展示，操作授权仍属于所选账号。
- 在线人数为当前Redis登录会话有效且用户状态/凭据版本仍有效的去重用户，不表示最近活动或页面实时在线。
- 顶部显示获得有效组织权益的组织数、用户数、在线人数。组织获得权益指非免费组织下至少有正常账号具备有效组织付费权益；按人的体验不计为免费组织0获得组织权益。用户数按身份去重，免费组织0在列表、邀请码和详情中明确显示。
- 组织新增地点文本；组织详情独立展示权益、账号容量/绑定/用户/在线、场次统计和账号明细，可生成组织邀请码，注册后绑定首次空闲账号并享该账号权益。不增加已交付容量、不通过邀请码换绑已有账号。

## 方案与边界

沿用现有PG/Redis及业务函数。新增组织地点列为可空文本，不回填猜测地址、不增加租户实体。统计由后端基于稳定账号与当前绑定汇总；登录会话按明确命名空间批量读取对应用户，不扫其他环境。系统配置只允许boss管理，敏感值服务端脱敏、按现有机制加密；受启动保护约束的连接/认证字段通过环境部署配置，不能由页面写入数据库覆盖。

新增运营接口覆盖用户资料、体验开启、邀请码、组织详情及地点、当前会话/强制下线、设置；商业交付和绑定继续复用已验证事务与固定请求号。体验/邀请并发及重试须保持一次效果。邀请码只决定绑定目标，不代替用户身份验证。2026-10-12用户明确确认：首次登录及新增绑定均采用密码、经过人机验证通道的短信验证码、微信API三种之一，包含平台管理员；微信尚未接入，界面禁用且后端拒绝。新用户注册的设定密码不是已有身份验证，仍须验证手机号。登录后总是显示竖向账号选择框，末行新增组织或账号；登录会话不因绑定而延长。

## 验收增量

1. 用户页看到个人资料及每个已绑定守望者账号的组织、角色、有效权益和期限；五类筛选与多账号汇总一致。
2. 免费账号开启体验30天，重复提交不延长，不改变自主资格；到期分类正确，普通账号不能调用平台体验管理。
3. 组织邀请码生成/复制/历史查看，0组织正确处理；邀请码注册可使用组织权益，空位耗尽拒绝且不新增容量。
4. 地点创建/编辑/组织详情展示一致；详情统计身份去重、正常/停用状态和有效会话口径正确。
5. 系统设置可读写普通配置，敏感值不下发明文、不被掩码覆写；不返回数据库连接/认证密钥，不开放环境保护键写入。
6. 本机验收入口更新并保留本轮已有合成数据；构建、隔离HTTP/PG/Redis和浏览器验证。用户仍负责最终产品验收。

## 实现与验证证据（2026-10-12）

- 运营快照、用户全部绑定权益/五类筛选、组织地点及独立统计详情、邀请码、后台30天体验、会话注销、设置读写均已接通。操作记录改为顶部次要抽屉，移除三项旧菜单。
- 平台登录支持密码或短信任选其一，包含平台管理员；人机SDK票据随发码请求提交，后端原通道仍二次核验。微信不可选择且接口返回暂不可用。正式环境未开启人机验证时拒绝短信单独验证，密码方式仍可用；测试环境保留模拟短信/关闭第三方人机服务，不宣称已经验证微信或真实短信渠道。
- 平台每次新模型登录均进入弹窗，竖向展示全部绑定账号及权益，末行“新增组织或账号”。邀请码新增绑定重新验证当前用户；成功刷新列表，用户选择新账号后进入对应入口。明确选择时才向对应前端保存该账号的登录状态；各前端仍使用不同存储键。绑定保持原会话标识和到期，不延长24小时，不覆盖用户资料，不增长已交付容量。
