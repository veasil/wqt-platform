## R1 主控决策清单

1. 创建应用、初始化运行依赖、启动监听、停止资源采用最少的明确函数入口，不新增通用依赖注入框架。
2. 避免导入时读取旧数据库连接或注册短信定时器；保持真实短信限流规则，不能为测试删除防护。
3. 测试主库与卡牌库都使用显式测试连接；禁用外部凭据继承，环境缺失时失败而非回退 localhost/wqt。
4. 真实 PG 环境先核实本机容器服务；若不可用，可使用隔离 CI 服务执行。测试基础设施只服务开发，不改变生产拓扑。
5. 保留旧初始化数据和清理业务行为；任何与原行为不一致的修复单独记录。
6. 独立模块文件尚未定义前，不让不同 Luna 各自实现互相冲突的接口。

## R1 内部接口与执行约束

- `createApp({ runtimeConfig, ossClient })`：同步装配 Express；允许创建路由和内存上传解析器，不执行数据库初始化、监听、配额或场次定时器。静态目录统一从现有 ROOT_DIR 解析，不能因文件移动改变 `/`、`/admin/`、`/enterprise/` 的资源位置。
- `startRuntime()`：显式执行现有启动顺序，返回 `{ app, server, stop }`；初始化失败时释放已创建资源。`stop()` 停止监听、定时任务和已初始化连接；重复调用不得创建新任务或连接。`server.js` 只加载启动环境并调用入口。
- 保留现有单例 DB API，R1 不要求同一进程运行多个不同数据库的应用实例。测试按子进程隔离，避免为了测试引入整套容器/依赖注入框架。
- 主库连接移到显式初始化时解析；卡牌继续支持独立连接配置，不把两套逻辑连接强行合并。生产初始化与种子逻辑保持原顺序，独立迁移框架延期。
- 测试控制器显式接收测试专用 PG 配置，使用临时实例或它独占创建的数据库，记录所有权并只清理自身资源。主库和卡牌都显式赋值；缺少配置时在导入业务模块前失败。不因 localhost 或名字包含 test 就推断数据库可以清空。
- 测试子进程使用环境白名单，先完成测试配置再动态导入应用；外部服务使用替身，不能继承数据库中已有生产凭据。无真实 PG 环境只执行无数据库测试并标注集成未验证。
- 生命周期接口由主控确定，Luna A 只在上述三个文件内提取；发现共享模块需要改动时返回主控，不扩大写入范围。Luna B 可先按接口编写测试，运行依赖 A/C 完成。接口调整由主控同步两方，不需要用户批准普通函数命名变化。
