## 目标与范围

最终目标：把现有 WQT 演进为职责清晰、可验证、可接续维护的模块化单体；Organization 为 Tenant，组织场次固定归创建时的组织。保留当前产品链路和 API 兼容，规划与证据进入 Git。

执行按 R1（测试隔离与启动拆分）→ R2/R3（平台与游戏模块）推进；T1（场次归属迁移）单独设计与验证。当前先运行只读盘点和制定任务契约，不把计划当作代码已经交付。

## 非目标

不引入微服务、通用插件引擎或新认证系统；不在重构中补齐全部 Learning 或创客营；不将本轮技术检查冒充完整 vNext 发布验收。不改变既有版本需求 ID、人工验收责任和生产批准。

## 验收标准

| ID | 验收结果 | 阶段与证据 |
|---|---|---|
| AC-01 | 任务可由另一 agent 根据制品、SHA、文件归属和下一步动作接续 | 每批 plan/evidence 中的交接状态 |
| AC-02 | 创建/导入应用不自动写库、监听或启动业务定时任务；运行进程显式初始化与释放资源 | R1 无数据库导入测试、启动/关闭与失败测试 |
| AC-03 | PG 集成测试的主库和卡牌库均显式隔离；缺少测试配置时拒绝启动，不继承生产凭据 | R1 失败路径及真实临时 PG 测试 |
| AC-04 | 平台与游戏入口可按模块定位；HTTP 契约、中间件顺序与现有授权行为保持 | R2/R3 路由清单对比、代表性成功/失败请求 |
| AC-05 | 人员由 A 转到 B 不改变已有场次组织归属；列表、详情、统计和写入均按规则验证 | T1 迁移与 A/B 组织反向测试，关联 TEN-001 |
| AC-06 | 登录→开局→事件→结算→复盘→组织查询完整链路可复现，数据库结果可对账 | 集成证据；关联 UI-002、TEN-001、TIME-001 |
| AC-07 | 每项验收有版本、结果和限制；重要 gate 与用户最终验收明确记录 | 最终验收包与 PR |

上述标准是对已确认目标的执行分解。新发现的历史归属歧义、权限改变和重大迁移风险进入重要 gate；日常任务与技术复核不请求用户重复确认。
