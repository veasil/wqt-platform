# design-workbench V4 验收标准实施方案

- 状态：已确认，待实施
- 日期：2026-09-08
- 目标分支：`codex/uiux-prototype`
- 工作目录：`design-workbench/`

## 目标

将新版验收标准落实到 `design-workbench`：统一术语与品牌素材，接入腾讯云真实安全验证，精简新游戏配置流程，重构游戏主页面的信息层级，为“我的”补齐既有活动码申请能力，并严格执行“先生图、后三轮代码还原”的视觉工作流。

## 一、术语与品牌规范

1. 建立术语表和自动扫描规则：
   - “守望师”统一为“守望者”。
   - “数字安全”“数字世界”等专业语境统一为“数智安全”“数智世界”。
   - 保留“数字权益”、表示数量的“数字”，以及法定公司名“上海伍仟天数字科技有限公司”。
2. 将“老师的分享”区域的公司 Logo 替换为透明底官方资产，不重新设计标识；校验四角透明度、比例和清晰度。

## 二、新游戏配置流程

新游戏调整为两步：

1. 活动选择页只展示用户有权限且当前正在开放的活动，点击活动即可进入下一步：
   - 活动状态必须为 `active`。
   - 非空时间范围必须满足 `start_at <= 当前时间 <= end_at`。
   - 移除手动活动码输入、地点、版本、模式、时长等非核心信息。
2. 第二页只配置三个阶段的卡牌数量，确认后开始游戏：
   - 标准成长模式：5000 秒、15 张，默认 `5/5/5`；允许重新分配，但总数必须为 15。
   - 快速成长模式：3600 秒、9 张，默认 `3/3/3`；旧名“快速体验模式”自动归一为“快速成长模式”。
   - 自定义模式：时长由活动预设；各阶段为非负整数、总数至少为 1，且不得超过对应卡牌组的可用数量。
   - 模式由活动预设，用户不在配置页选择模式；版本、时长和卡牌组均不显示。
3. 开局时客户端只提交活动码和阶段卡牌数量；服务端根据活动记录推导模式、时长、版本和卡牌组，拒绝隐藏字段篡改。

## 三、游戏主页面

1. 将“01 本局游戏状态”“03 伍力技能”“04 开局督导模式”统一收纳到左侧折叠栏，同一时间只展开一项。
2. 桌面端展开层覆盖在决策区左侧，不压缩核心操作区；窄屏使用抽屉层。支持点击外部关闭、`Esc` 关闭和关闭后焦点回归。
3. “输入卡牌编号”成为最高视觉层级：提高亮度、对比度和阴影，开局及处理完一张卡后自动聚焦。
4. “选择卡牌”保留单一 Logo 图标，不展示额外卡牌说明；图标提供 `aria-label`、标题和键盘焦点状态。
5. 空状态只保留“下一张情景牌正在等你开启”，移除“浏览本局可选卡牌”。

## 四、“我的”活动码

1. 新增“活动码”页签，直接复用后端已经存在的活动申请与审批模型，不新建数据库表。
2. 支持提交活动名称和地点，并展示待审批、已通过、已拒绝状态。
3. 只有 `active` 状态可以返回、展示和复制活动码；待审批及拒绝状态必须在接口和界面两层隐藏活动码。
4. 复用：
   - `POST /api/activities/apply`
   - `GET /api/me/activities/created`
5. `design-workbench` 的独立开发 API 只实现与生产后端一致的兼容适配，不建立第二套领域模型。
6. 更新 `CARD_GAME_CONTRACT.md`，补齐已经存在但尚未写入契约的活动申请、审批及活动码可见性规则，并同步新的模式与开局配置语义。

## 五、腾讯云真实安全验证

1. 接入腾讯云验证码 2.0 浏览器组件，加载官方 `TJCaptcha.js`。
2. 用户必须完成真实点击交互；前端取得 `ticket` 和 `randstr` 后交给服务端调用 `DescribeCaptchaResult` 二次核验。
3. 正式化以下接口：
   - `GET /api/auth/captcha/config`：只返回提供方、启用状态和公开 App ID。
   - `POST /api/auth/captcha/verify`：验证成功后签发与客户端/IP 绑定、120 秒有效、单次使用的安全凭证。
4. 登录或受保护操作消费安全凭证；过期、重放、客户端不匹配和腾讯云验证失败一律拒绝。
5. 缺少腾讯云凭据时必须失败关闭并显示明确配置错误，不得回退为模拟成功。
6. 当前采用“代码先行、凭据后补”；真实点击成功是凭据补齐后的强制发布门禁，在此之前不得宣称安全验证最终验收通过。

## 六、生图与三轮代码还原

1. 使用生图模型为现有全部页面和关键状态建立 V4 视觉基准，包括欢迎、登录与验证码、活动选择、三种配置模式、游戏主界面与三个折叠栏、编号输入反馈、快速选牌、复盘、个人中心和活动码状态。
2. 所有基准图及其提示词清单完成后，才开始 V4 页面代码调整。
3. 三轮实现顺序：
   - 第一轮：结构、信息层级和组件布局。
   - 第二轮：字体、间距、色彩、阴影和交互状态。
   - 第三轮：品牌素材、响应式、异常状态和像素级收敛。
4. 每轮保存优化后的页面截图、对比结果和验证 JSON，形成可追溯证据。
5. 主验收视口固定为 `1440x900`：
   - 关键矩形误差不超过 4px。
   - 关键颜色 `Delta E <= 3`。
   - 品牌与插画素材必须完全一致。
   - 动态文本及第三方验证码区域遮罩后 `SSIM >= 0.99`。
6. 补充验证 1366、1920 宽屏和 926、768 窄屏布局。

## 七、测试与验收

1. 术语扫描覆盖源码、界面文案和本轮文档，并为允许保留项建立白名单。
2. API 测试覆盖：活动权限与开放时间、固定模式总数、自定义模式边界、隐藏参数篡改、活动码状态脱敏、验证码失败/过期/重放。
3. 浏览器端到端测试覆盖：登录、选择当前活动、配置阶段数量、开始游戏、输入编号、图标选牌、折叠栏以及活动码申请与状态展示。
4. 验证所有目标视口无横向溢出、无控制台错误、无页面异常，并完成生产构建。
5. 腾讯云凭据补齐后，执行一次真实网络环境下的人工点击验证并保存结果，作为最终验收证据。

## 八、Git 版本管理

1. `design-workbench/` 采用精编入库：跟踪源码、必要品牌资产、契约文档、锁文件、V4 生图基准、三轮压缩截图和对比报告。
2. 排除 `.env*`、密钥、`node_modules`、`dist`、缓存、`.tools`、运行时数据库及 WAL/SHM、旧 V2/V3 截图和废弃原型。
3. 使用脱敏 JSON fixture 和构建脚本重建开发卡牌数据库，不提交真实手机号、真实业务数据或可变 SQLite 文件。
4. 后续实施拆分为三个可审查提交：
   - 精编后的 `design-workbench` 基线入库。
   - 业务流程、接口契约和腾讯云验证。
   - V4 视觉资产、三轮还原及验收证据。
5. 所有暂存操作使用明确的 `design-workbench/...` 路径，不使用全仓库批量暂存，避免混入现有无关文件。
6. 默认只提交当前分支，不推送、不部署。
