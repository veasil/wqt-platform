# 《伍力全开》桌游计分系统 · React 正式版工作台

这是下一代计分系统前端的独立开发工作台，目标是通过验收后替换现有 `public/` 原生前端。当前生产代码、API 和数据库均未修改。

## 技术结构

- React 19：界面与交互状态
- Vite 7：开发、构建与资源处理
- `src/components/`：桌游、监督、我的、登录和游戏配置组件
- `src/data/`：可重复的本地开发数据
- `src/services/api.js`：现有 Express API 的统一接入层
- `src/services/gameService.js`：演示/生产双运行时，界面只依赖统一业务服务
- `src/services/recordingService.js`：浏览器麦克风、录音生命周期与上传

## 本地运行

```powershell
npm install
npm run cards:dev
npm run dev
```

在两个终端分别运行 `cards:dev` 与 `dev`，然后访问 `http://127.0.0.1:4173/`。`cards:dev` 只针对 workbench，以只读数据库副本模拟会话内联想、逐张发牌和作答结算；不提供全量卡牌接口。

生产构建：

```powershell
npm run build
```

构建结果位于 `dist/`。Vite 使用相对资源路径，便于后续由 Express 静态托管。

## 当前演示路径

1. 启动页进入伍力世界。
2. 按住完成人机验证并登录。
3. 点击当前可用活动，或输入活动码读取配置；可修改活动名称、2025/2026 卡牌版本、模式、倒计时和各时期卡牌数。
4. 开始游戏；既可以输入编号联想，也可以按“时期 → 所属安全 → 卡牌”全程鼠标选卡。
5. 直接选择 A/B/C，查看数据库反馈和对应时期圆点；反馈会持续保留到打开下一张卡。
6. 打开卡牌后发动创心力，可键盘或语音输入任意办法生成 D，再请小伍确认 A/B/C/D。技能只要发动就会消耗并使创心力 +1。
7. 作答后可在反馈区播放反馈语音；服务端只接受答题授权绑定的反馈文本。
8. 切换监督模式，查看企业数据库连接、按卡牌组理论满分归一的雷达图/综合得分率、五力控制、游戏状态与可展开伍力理由的审计历史。
9. 切换“我的”；“我的学习”只负责跳转到独立 learning 网页，不在计分系统内加载课程。
10. 暂停或停止游戏，生成复盘报告。
11. “我的”可真实修改资料和密码、查看登录设备、下载复盘/录音并提交产品反馈；技术支持工单可创建、列表查看、追踪状态、阅读消息并继续追问，且会自动带上会话上下文。

## 数据接入

默认 `VITE_DEMO_MODE=true`，登录身份、活动、会话和事件写入独立 `data/test-wqt.db`；真实卡牌仍从只读卡牌库按会话逐张读取。三个内部测试账号使用生产手机号与业务角色结构，但使用统一的独立测试密码，不含生产密码哈希、OpenID 或生产会话。正式接入时复制 `.env.example`，设置 `VITE_DEMO_MODE=false` 与 `VITE_API_BASE_URL`。登录、活动、开局、单张卡牌、作答、`skill_used` 和结束结算均通过统一运行时调用。

测试站的服务不是静态占位：验证码走与生产相同的 Bmob 通道和限流规则，复盘走真实 DeepSeek 服务，TTS 走火山引擎；密钥只保留在服务端。录音、复盘文件、支持工单和用户反馈使用独立测试库与 Workbench 私有目录，避免污染生产业务数据。自动化验收不会主动向测试人员发送短信。

“我的学习”属于独立 learning 网页，计分系统只提供入口。卡牌全量内容、版本与发布管理只允许在 admin-web 中由受权角色访问。卡牌逐张发放、时期和计分规则见 [`CARD_GAME_CONTRACT.md`](./CARD_GAME_CONTRACT.md)。

桌游模式不会常驻展示五力分数；完成任意一个时期时才出现该时期结算和五力分数。卡牌进度按照服务端解析后的卡牌时期计入对应时期；`2026D08` 归入青春期。
