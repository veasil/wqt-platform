# 《伍力全开》卡牌、时期与计分契约

版本：2026-08-25

本文件是 React 前端、Express API、卡牌数据库和复盘事件之间的业务契约。实现冲突时以本契约与真实发布快照为准，不以界面文案或卡牌编号猜测业务字段。

## 1. 内容域与访问边界

卡牌库与课程库是两个独立内容域，不得因为都出现在“我的”模块而复用数据接口。

| 使用方 | 可以读取 | 禁止读取 |
| --- | --- | --- |
| 桌游玩家端 | 已登录且已开局会话当前获准的一张卡、提交选择后该选项的反馈 | 卡组目录、其他卡牌、未选选项反馈、全量发布快照 |
| 监督模式 | 本场已经发放的卡牌摘要、游戏状态与操作事件 | 未发放卡牌和全量卡牌库 |
| “我的学习” | 课程目录、章节、课时、学习进度与课程权益 | `cards`、`card_versions`、`cards_released` |
| admin-web | 按 `boss` / `operator` 权限管理全量卡牌、版本、发布快照和卡牌组 | 无权限角色的数据 |

生产玩家端不得调用可一次返回卡组内容的 `GET /api/cards`。现有公开 `GET /api/cards` 与 `GET /api/card-groups` 属于迁移前接口：完成逐张发牌接口后应移出公开玩家链路，完整管理能力只保留在 admin-web 的受权接口中。

当前 workbench 通过本地只读数据库副本模拟会话内联想、逐张发牌和作答接口，并已关闭全量卡牌端点；它用于验证生产接口形状，不改动生产数据库。

### 1.1 生产逐张发牌

生产链路建议由服务端持有活动配置、卡组顺序、已发卡集合、时期进度和计分状态：

```http
POST /api/game/start
POST /api/game/card/resolve
POST /api/game/card/answer
```

- `start` 校验 JWT、活动码、账号权益并创建会话，不返回完整卡组。
- `resolve` 接受会话 ID 与用户输入的编号，只返回当前获准卡牌的题面和可选项；同一会话同一时间最多有一张待作答卡。
- `answer` 接受当前卡牌授权和最终选项，由服务端结算；只返回已选选项反馈、分数变化和新的时期进度。
- 每次发卡和作答写入会话、用户、组织、IP/设备摘要、时间、卡牌 ID 与请求 ID，便于审计和异常批量抓取告警。
- 响应使用 `Cache-Control: no-store`；音频使用短时签名地址。浏览器端不持久化卡牌正文。

### 1.2 单张卡牌响应示例

逐张发牌响应可沿用下列真实字段，但只包含本次获准的一张卡：

```json
{
  "cards": [
    {
      "id": 98,
      "key": 99,
      "card_code": "2026D08",
      "safetyType": "数字权益",
      "event": "情境正文",
      "phase": "青春期",
      "audio_url": null,
      "title": "AI换脸是开玩笑吗？",
      "guide_text": "引导语",
      "options": {
        "A": {
          "text": "选项正文",
          "consequence": "反馈正文",
          "attributeEffects": { "安全力": 1 }
        }
      }
    }
  ],
  "group": { "id": 6, "name": "2026版", "maxScores": {} }
}
```

前端不得修改 `phase`、`options` 或 `attributeEffects`，不得把本地演示卡与真实卡混合进入正式对局。服务端必须再次校验卡牌属于当前活动卡组，不能信任客户端提交的卡牌正文、反馈或分数。

### 1.3 “我的学习”课程域

“我的学习”是一整套课程产品的入口，不是卡牌浏览器或游戏历史的改名版本。课程端至少需要独立的课程目录、章节/课时、学习进度、完成状态与权益校验接口；数据模型和权限在课程 PRD 确认后单独定稿。

现有 `/api/me/study/cards` 不接入 React 新版“我的学习”，迁移完成后应评估下线或仅为旧客户端保留兼容期。

## 2. 卡牌编号

- 正式唯一编号使用 `card_code`；经典卡没有 `card_code` 时回退 `id`。
- 输入允许省略版本前缀，例如在 2026 卡组中输入 `D08` 可匹配 `2026D08`。
- UI 可显示短编号 `D08`，事件与接口必须保留完整编号 `2026D08`。
- 编号本身不决定时期；时期只读取卡牌的 `phase`。


## 3. 时期进度

本局配置：

```json
{
  "cardsPerPhase": {
    "启蒙期": 5,
    "成长期": 3,
    "青春期": 4
  }
}
```

前端运行态使用按时期独立计数：

```json
{
  "phaseProgress": {
    "启蒙期": 0,
    "成长期": 0,
    "青春期": 0
  }
}
```

结算公式：

```text
phase = completedCard.phase
phaseProgress[phase] = min(cardsPerPhase[phase], phaseProgress[phase] + 1)
remaining[phase] = max(0, cardsPerPhase[phase] - phaseProgress[phase])
```

完成一张成长期卡只减少成长期剩余张数，启蒙期和青春期不变。允许现场按任意顺序抽取不同阶段卡牌。

缺失或非法 `phase` 的卡牌不能结算，前端显示错误并禁止写入 `card_choice`。

## 4. 分数显示

- 综合伍力得分率与旧正式版统一：每个维度先计算 `当前分 / 当前卡牌组该维度理论满分`（最高 100%），再对五个维度得分率取平均并四舍五入。
- 禁止使用“五项当前分求和 ÷ 固定 50”的新算法。理论满分由服务端按本局去重后的卡牌集计算，前端、结束入库和复盘必须使用同一结果。
- 桌游模式日常操作期间不显示 R/A/S/P/E 数值。
- 监督模式可以持续显示五力值，供督导观察。
- 任意时期从“未完成”首次变为“完成”时，桌游模式弹出一次阶段结算。
- 阶段结算展示当前五力总分和五项分数，关闭后不在桌游模式常驻。
- 同一时期不得重复弹出阶段结算；恢复会话时必须恢复已结算时期集合。

## 5. 卡牌反馈

- A/B/C 的反馈正文直接使用 `option.consequence`。
- 分数变化直接使用 `option.attributeEffects`，允许正数、零和负数。
- 反馈显示卡牌短编号、最终选项、各维度变化和反馈正文。
- 反馈固定放在中部卡牌区下方，持续显示到用户打开下一张卡。
- 反馈出现后禁止重复提交当前卡牌，但允许阅读、滚动和调取下一张卡。

## 6. 五力技能

- 每种技能每局一次。
- 除安全力外，发动技能立即写入 `skill_used`，对应力 +1；之后选择 A/B/C 也不撤销技能消耗与技能分。
- 安全力技能是例外：发动后显示一次“安全力警告”悬浮窗，公开当前五力值及相对本局初始值的扣分分析。
- 安全力扫描时，所有恰好等于 `1` 的力值分别获得紧急救援 `+1`；没有 `1` 分力值时只展示分析，不额外加分。技能仍视为已使用。
- 安全力事件必须同时记录 `before`、`after` 和 `rescuedPowers[]`，确保复盘可以解释救援来源，不能把救援分重复算作卡牌分。
- 创心力生成 D 后，小伍确认最终 A/B/C/D。
- 最终 A/B/C：按真实卡牌选项的 `attributeEffects` 再结算卡牌，同时保留创心力技能 +1。
- 最终 D：技能 +1 已在 `skill_used` 结算；D 本身默认不重复加创心力，审核反馈记录在 `card_choice`。
- 创心力只能在“当前已打开卡牌且尚未选择选项”时发动；无卡牌或已出反馈时按钮必须禁用。
- D 的反馈由服务端调用 LLM 生成，提示词必须包含当前卡牌的完整结构数据以及同时期/同安全类型的结构化卡牌样例。服务不可用时回退到本地五维度结构化反馈，不得让作答丢失。

## 7. 游戏事件

卡牌选择：

```json
{
  "sessionId": 123,
  "type": "card_choice",
  "payload": {
    "cardId": 98,
    "cardCode": "2026D08",
    "phase": "青春期",
    "safetyType": "数字权益",
    "eventText": "情境正文",
    "choice": "C",
    "optionText": "选项正文",
    "consequence": "反馈正文",
    "attributeDelta": { "安全力": 1 },
    "isCreativeOption": false
  }
}
```

技能：

```json
{
  "sessionId": 123,
  "type": "skill_used",
  "payload": {
    "skill": "creative",
    "power": "创心力",
    "cardCode": "2026D08"
  }
}
```

`skill_used` 与 `card_choice` 必须分开，复盘和计分不得合并或重复累计。

安全力紧急救援事件示例：

```json
{
  "sessionId": 123,
  "type": "skill_used",
  "payload": {
    "skill": "safety",
    "power": "安全力",
    "effect": "emergency_rescue",
    "before": { "safety": 3, "reason": 1, "sense": 2, "creative": 3, "empathy": 1 },
    "after": { "safety": 3, "reason": 2, "sense": 2, "creative": 3, "empathy": 2 },
    "rescuedPowers": ["脑波力", "沟通力"]
  }
}
```

## 8. 开局与结束接口

开局：

```json
{
  "activityCode": "WQT-0820",
  "mode": "标准成长模式",
  "cardGroupIds": [6],
  "settings": {
    "deckVersion": "2026 版",
    "duration": 5000,
    "cardsPerPhase": { "启蒙期": 5, "成长期": 3, "青春期": 4 }
  }
}
```

结束：

```json
{
  "sessionId": 123,
  "endedAt": 1787568000000,
  "finalScore": 18,
  "attributes": {
    "安全力": 4,
    "脑波力": 4,
    "实感力": 3,
    "创心力": 3,
    "沟通力": 4
  },
  "payload": {
    "activityCode": "WQT-0820",
    "phaseProgress": { "启蒙期": 0, "成长期": 0, "青春期": 1 }
  }
}
```

结束接口中的 `attributes` 统一使用数据库现有中文维度名；React 内部 key 只允许存在于组件状态，提交前必须由 API 适配层转换。

## 9. 会话恢复

必须恢复：卡组 ID、完整卡牌编号、各时期独立进度、五力值、已使用技能、已结算时期、最后一条反馈、暂停状态和服务端倒计时基准。会话 ID 使用 `sessionStorage`，避免多标签页串号。

## 10. 活动、快速选卡与语音契约

- 登录后只能读取当前账号有权限参与的 `active` 活动；玩家端不存在“列出所有生产活动”的接口。
- 活动点选返回活动名、活动码、卡牌版本、游戏模式、倒计时、时期张数和 `cardGroupIds[]`；开局前这些配置可编辑，服务端保存本局快照。
- 快速选卡严格按“时期 → 安全类型 → 可用卡牌”三步：前两步只返回数量，最后一步只返回编号、标题、时期、安全类型和不可猜测的 `cardRef`。
- 卡牌正文、ABC 文案和反馈不得随快速选卡列表批量返回；用户点击一张后才用 `cardRef` 换取一张完整卡牌。
- 已作答卡牌不再进入联想和快速选择；某时期完成活动预设张数后，该时期不再发放新卡，但进度不清零。
- `2026D08` 的产品契约时期为“青春期”，Workbench 不得再用运行时覆盖将其改为其他时期。
- 创心力 D 输入支持浏览器中文语音识别，识别结果必须可编辑；权限拒绝、无支持和识别失败均回退到键盘输入。
- 答题后服务端签发一次性 `feedbackGrantId`。反馈 TTS 只能朗读该授权绑定的反馈文本，客户端不得提交任意文本调用 TTS。
- 卡牌与反馈语音使用同一音色版本和缓存策略；缓存键至少包含文本、音色、语速和资源版本。

## 11. 测试数据边界

- Workbench 使用独立 `test-wqt.db`，表名和核心字段保持生产结构：`users`、`organizations`、`activities`、`game_sessions`、`game_events`、`user_sessions`。
- 测试账号可复制生产手机号、角色、守望师等级和有效期；禁止复制生产密码哈希、OpenID、UnionID 和生产会话令牌。
- 测试密码使用独立哈希，测试会话与事件只写入 Workbench 数据库，不回写生产。
