# 《伍力全开》桌游计分系统 React 重构与生产迁移计划

更新日期：2026-09-02

## 1. 项目目标

在独立 workbench 中完成可长期维护的 React 正式版前端，通过业务验收、接口联调和回归测试后替换现有原生 HTML/CSS/JS 前端。迁移期间保持现有生产系统可用，并保留可快速回滚的旧版静态资源。

本阶段不修改 `wqt-auth-backend/public/`、`server.js` 或数据库。

## 3. 正式版信息架构

顶部仅保留三个主 Tab：桌游模式、监督模式、我的。切换不刷新页面，对局计时和状态不丢失。

### 3.1 桌游模式

单屏工作区由三列构成：

- 左侧“01 本局游戏状态”：当前卡片、活动码、卡牌版本、游戏模式、时期进度、暂停、停止并复盘。
- 中部卡牌决策台：顶部卡牌编号联想输入、大卡、语音、ABC/D 决策和可持续阅读的反馈区；不常驻展示五力分数。
- 右侧“03 五力技能”：R 安全力技能、A 脑波力技能、S 实感力技能、P 创心力技能、E 沟通力技能。
- 右侧“04 开启督导模式”：现场录音、进入监督模式、联系技术支持。

删除独立“02 五力状态”面板、准备抽卡说明、技能使用说明和英文装饰标签。五力数值进入卡牌决策上下文，减少视线移动。

### 3.2 监督模式

- 页面顶部明确展示“监督模式”。
- 绿点状态文案为“连接企业数据库”。
- 保留五力雷达、五力控制面板、游戏状态和操作历史。
- 删除“数据安全任务仓”“任务仓在线”。
- 监督调整必须记录为事件，正式接入时带操作者与时间戳。

### 3.3 我的

“我的”不再是独立旧页面，而是 React SPA 内的正式模块。延续旧版账户资产能力并升级为：账户资料、权益与期限、安全设置、我的学习、文件与反馈。点击顶部头像或“我的”Tab 均可进入。

“我的学习”只提供前往独立 learning 网页的入口，课程功能不在计分系统中实现。全量卡牌、版本、选项反馈、发布和卡牌组管理只存在于 admin-web，并受 `boss` / `operator` 权限控制。

## 4. 核心业务状态机

### 4.1 登录与开局

1. 账密登录或验证码登录。
2. 通过人类验证。
3. 输入活动码。
4. 系统读取活动绑定的卡牌组、2025/2026 卡牌版本、模式、倒计时和时期张数。
5. 有权限的用户可在开局前修改本局配置。
6. 创建游戏会话并进入桌游模式。

### 4.2 时期进度

活动配置只约束每个时期要完成的卡牌张数。进度使用实心/空心圆点展示，每次作答按卡牌快照自身的 `phase` 更新对应时期，不按累计总张数推断时期。时期之间互不清零，目标张数由本局配置驱动。

### 4.3 卡牌自动流转

1. 输入卡牌编号，联想当前卡组中的卡牌。
2. 点击联想项，大卡进入决策台。
3. 玩家点击 A/B/C，或通过创心力生成 D。
4. 系统展示反馈、记录事件、更新五力和时期圆点。
5. 反馈固定显示在中部卡牌区下方，直到打开下一张卡，保证现场有足够阅读时间。
6. 桌游模式不常驻展示伍力分数；任意时期首次达到目标时，弹出该时期结算与五力分数。

### 4.4 创心力

1. 发动 P 创心力技能时立即标记为已使用，创心力 +1。
2. 用户可输入任意文本，系统据此生成选项 D。
3. 由小伍确认最终 A/B/C/D。
4. 最终选择 A/B/C 时，创心力技能仍已消耗，技能分不撤销；卡牌按最终选项正常反馈。
5. 最终选择 D 时进入审核并获得对应反馈。
6. `skill_used` 与 `card_choice` 分别记录，避免复盘把技能分和卡牌分混为一条事件。

### 4.5 停止与复盘

停止游戏后立即冻结计时、选择、技能和写入操作，再调用结束会话与报告生成。报告至少包含本局摘要、五力变化、关键决策、现场录音引用和下一步成长建议。生成失败时允许重试，不能重复结算分数。

## 6. API 接入清单

| 链路 | API | 迁移要求 |
| --- | --- | --- |
| 登录 | `POST /api/auth/login` | 复用短信、人机验证、限流与单设备会话 |
| 当前用户 | `GET /api/me` | 驱动“我的”和头像 |
| 活动预设 | 待确认 | 服务端解析活动码、卡组与阶段目标，不向前端暴露完整卡组 |
| 单张卡牌 | 待新增会话内逐张接口 | 登录并开局后按编号解析一张，不提供卡组批量下载 |
| 卡牌作答 | 待新增服务端结算接口 | 返回已选反馈、分数变化与时期进度 |
| 开局 | `POST /api/game/start` | 返回并保存 session ID |
| 卡牌/技能事件 | `POST /api/game/event` | 使用 `card_choice` / `skill_used` |
| 结束 | `POST /api/game/finish` + `/api/game/review` | 幂等结算，基于真实事件生成并缓存复盘 |
| 现场录音 | `POST /api/game/recording` | 会话鉴权、文件元数据落库、用户文件可下载 |
| 技术支持 | `POST /api/support/tickets` | 自动关联用户、会话和页面上下文 |
| 我的学习 | 待课程 PRD 定稿 | 独立课程目录、课时、进度与权益接口，不读取卡牌库 |
| 卡牌管理 | admin-web 受权 API | 仅 `boss` / `operator` 查看和管理全量内容 |

当前后端端点列表没有“按活动码读取开局预设”和“会话内逐张发牌/作答”的完整接口。正式联调前需补齐；React 端不应自行拼装生产活动配置或下载全量卡牌。现有 `GET /api/cards` / `GET /api/card-groups` 仅用于 workbench 真实字段走查，不能作为生产玩家端方案。

## 7. 稳定性与生产要求

- 进行中会话 ID 放 `sessionStorage`，不同标签页互不串号；JWT 继续放现有认证存储。
- 页面刷新后通过服务端恢复会话、时期、技能使用状态和倒计时基准。
- 结束状态必须统一阻止计分、事件写入和技能消耗。
- 卡牌选择、技能和结束接口使用幂等键，网络重试不重复加分。
- 现场录音需显示权限拒绝、上传中、上传失败和已保存状态。
- 技术支持入口首版接入工单/反馈表，并自动附带前端版本、会话 ID 和最近错误摘要，不上传敏感卡牌内容。
- 支持 1440×900、1366×768 和 1920×1080；低高度设备允许工作区内部滚动，不遮挡关键操作。
- 满足键盘焦点、减少动态效果和基础对比度要求。

## 9. 验收用例

- 欢迎页、品牌名、产品名和系统名完全符合规范。
- 登录两种渠道与人类验证均可操作。
- 活动码配置可读取、可按权限修改，并支持 2025/2026 版本。
- 本局状态准确展示当前卡片、活动码、版本和模式。
- 时期圆点按卡牌自身 `phase` 递增，其他时期不变。
- 选择卡牌后反馈持续显示到下一张卡，不需要重复确认。
- 桌游模式默认无五力分数；只有时期完成结算时显示。
- 创心力最终选 A/B/C 时仍标记技能已使用且创心力 +1；选 D 时进入审核反馈。
- 五力技能名称全部为“R/A/S/P/E + 对应力技能”，不出现 5D 按钮。
- 监督模式顶部存在“监督模式”和“连接企业数据库”，不存在已删除文案。
- “我的”可从顶部 Tab 和头像进入；“我的学习”只跳转独立 learning 网页，不在计分系统中加载课程或卡牌。
- 普通玩家与监督模式无法批量读取卡组；只有 admin-web 的受权角色可以查看全量卡牌。
- 暂停后计时和写操作冻结；停止后只结算一次并能获得复盘报告。
- `npm run build` 成功，浏览器无错误覆盖层和阻断性控制台错误。
